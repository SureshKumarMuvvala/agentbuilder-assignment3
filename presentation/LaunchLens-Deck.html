The Product

Founders guess. LaunchLens checks.

Before building anything, a founder needs to know two things: is there demand, and who already supplies it? Today that means hours across Google Trends, news, and Amazon — done by hand, never fused.

LaunchLens collapses that into a single sentence in, a single verdict out:

  • Type an idea — “insulated steel water bottle in India under ₹1,500”
  • It researches both sides — demand (SerpApi) + supply (Oxylabs)
  • It fuses + decides — GO / NICHE / NO-GO with price band & positioning
  • It remembers — follow-ups keep context; long chats auto-summarize

Every verdict ships with receipts

Demand score, supply/competition, a recommended price band, and the top unmet gap mined straight from competitor reviews — each traceable to the tool call that produced it.

How it works · one pass

Idea → research → fuse → verdict

A single LangGraph state machine runs the whole turn. Read left-to-right it is also the rubric — the five graded LangGraph concepts in execution order.

Memory

summarize_if_needed compresses old turns before they overflow context.

Routing

classify_intent labels the question, a conditional edge picks the path.

Fan-out

Send() launches the research nodes in one parallel superstep.

Agent + Tools

create_react_agent fuses demand + supply into the verdict.

Typed State

LaunchLensState with reducers merges concurrent writes safely.

A grader can identify all five — Graph, Routing, Fan-Out, Agent+Tools, Memory — in under 30 seconds, live in the UI.

The router doesn’t call the research nodes in sequence — it returns a list of Send() objects, so LangGraph launches every targeted node in the same superstep and waits for all of them before the agent runs.

Each branch writes a different key into one research dict; the operator.or_ reducer merges them without clobbering. That merged dict is what the agent fuses.

SqliteSaver checkpoints state after every node — keyed by thread_id, so the next turn remembers.

  • Google News — category momentum
⊕

  • Amazon Search — sellers, ratings, price band
  • Amazon Reviews — recurring complaints = gaps
→

Fused verdict

Rising demand + a price gap + an unmet review complaint = GO, with where to enter and what to win on.

The agent never sees two siloed payloads. It receives one merged research dict and is told to fuse both sides — demand justifies the “why now”, supply justifies the “where’s the gap”, and the price band comes from reconciling Shopping vs Amazon.

Data-Fusion · discipline

Slim signals, never raw payloads

Every tool returns a small structured dict (< 200 bytes) — never the raw API response. This keeps the LLM context clean, the fusion cheap, and the trace readable.

  • Demand distills to a score + direction + related terms
  • Supply distills to seller count, price band, top complaints
  • Errors degrade gracefully — a failed live call returns {"error": …}, never crashes the graph
  • Mock mode serves the same shapes from fixtures — deterministic, offline, free
# google_trends → demand signal { "trend": "rising", "avg_interest": 59, "related": ["insulated steel water bottle", "leakproof flask 1l"] } # amazon_search → supply signal (Oxylabs) { "sellers": 5, "rating": 4.1, "low": 649, "high": 1999, "top_asin": "B0AAA11111" }

Feature · Timeline

Proof the fan-out is real, not sequential

The Timeline tab lists every node execution with its superstep and duration. The tell-tale of true parallelism:

  • Memory Check = step 1, Intent Router = step 2
  • All five research nodes share step 3 — they ran together, not one after another
  • Verdict Agent = step 4, after the merge
  • Per-node durations make the cost of each call legible

Shared step number = same superstep = genuine Send() fan-out.

Feature · Tool Trace

Every tool call and its slim result

The Tools tab shows each research call as it fired:

  • Tool name + a colour-coded source tag — demand · SerpApi supply · Oxylabs
  • The exact input keyword — extracted from the question (“stainless-steel insulated water bottle india”)
  • The slim structured output the LLM actually consumed — trend, price band, headlines, complaints
  • Status per call, so a degraded live call is visible at a glance
Feature · State

The typed state, merged live

The State tab exposes LaunchLensState as it stood at the end of the turn:

  • intent (routing) — full → 5 branches
  • search keyword — the cleaned product term sent to every tool
  • research — the one dict merged via operator.or_, with every branch’s key (trends, shopping, news, amazon, reviews)

This is the reducer doing its job: five concurrent writes, zero clobbering.

Feature · Memory

Memory you can see grow

The Memory tab shows evolution across all turns, not just the latest:

  • Each turn’s message count + checkpoints written by SqliteSaver
  • Turn 2 (“What about the US market instead?”) keeps the bottle context — the follow-up works without restating it
  • The bar grows toward the summarize threshold (10); past it, summarize_if_needed compresses older turns
  • Each turn keeps its own trace — older runs are never overwritten

Under the Hood

Stack & design rules

Data

Design rules that shaped it

  • Slim tool output — < 200 B dicts, never raw payloads
  • Three LLM modes — mock / openai / anthropic, one env var, switchable at runtime
  • Mock-first — fixtures make the whole demo offline & deterministic
  • Graceful errors — try/except per live call, never crash the graph
  • Beginner comments — every node/tool explains purpose, in/out, why
  • Same graph, two front-ends — CLI & web share one compiled graph
