How it works · one pass

Idea → research → fuse → verdict

One LangGraph state machine runs the whole turn. Read left-to-right it’s also the rubric — the five graded LangGraph concepts, in execution order.

Memory

summarize_if_needed compresses old turns before context overflows.

Routing

classify_intent labels the question; a conditional edge picks the path.

Fan-out

Send() launches the research nodes in one parallel superstep.

Agent + Tools

create_react_agent fuses demand + supply into the verdict.

Typed State

LaunchLensState with reducers merges concurrent writes safely.

A grader identifies all five — Graph, Routing, Fan-Out, Agent+Tools, Memory — in under 30 seconds, live in the UI.

The router returns a list of Send() objects, so LangGraph launches every targeted node in the same superstep and waits for all before the agent runs.

Each branch writes a different key into one research dict; the operator.or_ reducer merges them without clobbering. That merged dict is what the agent fuses.

SqliteSaver checkpoints state after every node, keyed by thread_id.

Data-Fusion · discipline

Slim signals, never raw payloads

Even live, every tool returns a small structured dict (< 200 bytes) — never the raw API response. The LLM fuses signals, not noise; the trace stays readable.

  • Demand distills to score + direction + headlines
  • Supply distills to seller count, price band, complaints
  • Errors degrade gracefully — a failed call returns {"error": …}, never crashes the graph
  • Same shapes as mock — so the fixture demo and the live run render identically
